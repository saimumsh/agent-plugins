# Input checklist

## Requirements Specification (required)
- [ ] Goal, users, scope / out of scope
- [ ] Functional requirements numbered (FR-n)
- [ ] Non-functional: scale (users, rps, data volume), latency, availability, privacy/compliance
- [ ] Constraints (budget, deadline, mandated tech, region/data residency)

## Feature List + Acceptance Criteria (required)
- [ ] Every feature has an ID, priority (MVP / later) and testable acceptance criteria

## Technical Standards (required)
- [ ] `_global.md` exists; feature standards exist for sensitive features (auth, payments, PII)

## User Journeys (optional)
- [ ] Main journeys with steps, actors, and failure paths

## Wireframes (optional)
- [ ] Screens for MVP features; fields and actions readable

## Threat Model (required to baseline)
- [ ] Assets, trust boundaries, threats (T-NN) with severity, required mitigations

## ADR Approvals (revision pass only)
- [ ] One approval per Proposed ADR

Record an assumption for every gap you continue past.
