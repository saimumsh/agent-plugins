# Input checklist

## Requirements Specification: must have
- [ ] Goal / problem statement
- [ ] Users and main scenarios
- [ ] Functional requirements (numbered, e.g. FR-1)
- [ ] Non-functional requirements: performance, security, availability, privacy/compliance
- [ ] Acceptance criteria (testable)
- [ ] Constraints, assumptions, out of scope

## ADR: must have
- [ ] Number, title, status (should be `Proposed`)
- [ ] Context linked to the spec
- [ ] A clear decision
- [ ] At least 2 alternatives with trade-offs
- [ ] Consequences, including what becomes hard to undo
- [ ] Cost / operational impact for new services

Missing spec or ADR entirely → INPUT NEEDED. Missing items → findings in the approval.
